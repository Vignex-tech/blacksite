### Shared contract (`shared/`)
- Plain ESM `.js` runtime files with `.d.ts` types, and `shared/package.json` (`"type": "module"`). The client imports `../../shared/<file>.js` and the server `../../../shared/<file>.js` (from `server/src/rooms/` or `server/src/rules/`).
- `protocol.js`: `ROOM_NAME` (`my_room`), `MOVE_MESSAGE` (`move`), `GROUND_SIZE` (40, centred on 0), `PlayerState` and `GameRoomState`. Added in M3 (#18):
  - `TEAMS`: frozen `['ghost', 'warden']`, equal to the keys of `GRAYBOX_MAP.spawnAreas`; type `Team = 'ghost' | 'warden'`.
  - `MAX_TEAM_SIZE` 4.
  - `TEAM_SPEED`: frozen `{ ghost: 2.4, warden: 2.0 }` world units/s (step per accepted move = speed / 20 Hz, so 0.12 and 0.1).
  - `MoveMessage { dx, dz, yaw? }`: camera-relative intent. `dx` is strafe (+1 right), `dz` forward (+1 forward), each -1..1. Yaw is in radians; 0 faces +z and positive turns toward +x (Babylon `rotation.y`). Forward is (sin yaw, cos yaw) and right is (cos yaw, -sin yaw) on (x, z). A missing yaw keeps the player's current yaw, so at yaw 0 the M2 meaning (W is +z, D is +x) still holds. `dx = dz = 0` with a yaw only turns.
  - `PlayerState { x, y, z, team, yaw, mode }`: `team` and `yaw` are required since #22, `y` (feet height) and `mode` since #33.
  Added in M4 (#27):
  - `MOVEMENT_MODES`: frozen `['ground', 'falling', 'climbing', 'hanging']`, type `MovementMode`.
  - `ACTION_MESSAGE` (`action`), frozen `ACTIONS` `['jump', 'climb', 'drop']`, type `Action`, and `ActionMessage { action }`. It carries **no anchor id or position**: the server picks the anchor from the player's own position, so there is nothing to forge. `climb` attaches to a climb anchor, grabs a ledge, or mantles from hanging. While climbing, `move.dz` climbs up or down; while hanging, `move.dx` shimmies (+dx is to the player's right when facing the ledge's `facing`, not the camera's).
  - Tuning constants (each in one place): `GRAVITY` 20, `MAX_FALL_SPEED` 20, `JUMP_SPEED` frozen `{ ghost: 4.5, warden: 0 }` (apex 0.506), `STEP_HEIGHT` 0.35, `CLIMB_SPEED` 1.5, `SHIMMY_SPEED` 1.0, `ANCHOR_RANGE` 0.8 (horizontal), `ANCHOR_REACH` 0.6 (vertical), `CAN_CLIMB` frozen `{ ghost: true, warden: false }`. `ACTION_RATE_HZ` and `ACTION_BURST` are server constants, not in `shared/`.
  Added in M5 (#39): `FIRE_MESSAGE` (`fire`, `{ yaw, pitch }`, pitch positive up on the wire), `RELOAD_MESSAGE` (`reload`), `MAX_HEALTH` (ghost 100, warden 150), `WEAPONS` per team (damage, intervalMs, magazine, reloadMs, range; Warden rifle 25/150/30/2000/40, Ghost sidearm 15/300/12/1500/25), `EYE_HEIGHT` 1.6, `FRIENDLY_FIRE` false, `VISIBILITY_NEAR` 2.0, `FIRE_RATE_HZ` 10, `FIRE_BURST` 3, and event names `SHOT_EVENT`, `HIT_EVENT`, `DAMAGED_EVENT`. `PlayerState` gains `health`, `ammo`, `reloading` (required on the client since #48). Event payloads: `hit` goes to the shooter, `damaged { damage, health, killed }` to the victim only (no shooter id or position), `shot` carries origin, end and hit (Warden shots to everyone, Ghost shots to Ghost clients only).

### Server (`server/`)
- Colyseus 0.18. `server/src/rooms/MyRoom.ts` and `schema/MyRoomState.ts`: `Player { x, y, z, team, yaw, mode }` in a `players` map keyed by sessionId. Vertical speed and the anchor a player is attached to are server-only (not synced). `maxClients` is `MAX_CLIENTS` (8 = 2 teams x `MAX_TEAM_SIZE`).
- `server/src/rules/` holds pure rule code with no Colyseus imports:
  - `collision.ts` (M3, still used for the ground band): `groundSolids` keeps solids whose y range overlaps 0..PLAYER_HEIGHT. `resolveMove` moves on x, then on z, each swept against those solids, so a box stops flush with the first face in its path at any step size and never tunnels. It then clamps the box inside the map bounds. Touching a face isn't overlap, so players slide along walls. Players don't collide with each other.
  - `teams.ts` (`assignTeam`): counts the players currently in the room and picks the team with fewer players; ties go to ghost. If that team already has `MAX_TEAM_SIZE`, the join is refused (onJoin throws). Join options are ignored (a forged `{ team: 'warden' }` does nothing). No rebalancing when someone leaves; a player keeps their team until they leave. A fresh room fills ghost, warden, ghost, warden.
  - `spawn.ts`: `randomSpawnPoint` picks a uniform point in `spawnAreas[team]`, tries up to 50 times to avoid solids, then falls back to the area's centre. Players spawn at yaw `SPAWN_YAW` (0). `joinCount` and `spawnAreaForJoin` are gone.
  - `movement.ts` (`parseMove`, re-exported from `MyRoom.ts`): the whole message is ignored if it isn't a non-array object with finite-number `dx` and `dz`, or if `yaw` is present and isn't a finite number. Ignored messages spend no rate-limit token. Each axis is clamped to -1..1 and the intent length is capped at 1 (so diagonals are normalised). Yaw is wrapped into -pi..pi and stored before the move; the intent is rotated by yaw and scaled by `TEAM_STEP[team]`, then collided and clamped to +-`BOUND` (19.5).
  - `vertical.ts` (#29): `moveBody`, `stepFall`, `startJump`, `supportHeight`, `rampTopOver`, `blockersAt`, `isClear`.
    - Walkable surfaces are the ground, floor tops and ramp tops. **Solid tops (walls, cover) are not walkable** (decided on #26). Support is the highest walkable surface under the box whose top is at most `y + STEP_HEIGHT`; ramp height is the wedge's highest point over the overlapped part.
    - Floors and ramp wedges block when they overlap `y + STEP_HEIGHT .. y + PLAYER_HEIGHT`; solids block when they overlap `support .. y + PLAYER_HEIGHT`, so nobody walks the wall ring from the mezzanine. A box may overhang a slab edge while it still overlaps the slab.
    - Grounded moves follow the support within `STEP_HEIGHT` up or down; a bigger drop switches to `falling`. Each axis is swept with face events. Falls are integrated exactly on the parabola and capped at `MAX_FALL_SPEED`, and landing is swept, so nobody falls through a 0.2 slab. A rising head stops flush under a floor underside.
  - `actions.ts` (#29, `parseAction`): anything that isn't a non-array object with `action` in `ACTIONS` is ignored and spends no token; extra fields are never read. `jump` works only from `ground` with `JUMP_SPEED[team] > 0` (Wardens can't jump).
  - `climbing.ts` (#31): `grab`, `climbMove`, `shimmy`, `mantle`, `letGo`, `nearestOnLedge`. Ranges are inclusive with 1e-9 tolerance.
    - `climb` from `ground` or `falling` is always refused when `CAN_CLIMB[team]` is false. Climb anchors are tried first: (x, z) within `ANCHOR_RANGE` of the centre and feet within `minY - ANCHOR_REACH .. maxY + ANCHOR_REACH`; the player snaps to the anchor with yaw set to `facing`, mode `climbing`. Otherwise ledges: the segment within `ANCHOR_RANGE` and `|y + 1.8 - ledge.y| <= ANCHOR_REACH`; the player snaps to the nearest segment point with feet at `ledge.y - 1.8` (1.2), mode `hanging`. The nearest anchor wins; a snap is refused if the box doesn't fit or the path crosses a solid or floor.
    - `climbing`: `dz * CLIMB_STEP` moves the feet within minY..maxY (dx ignored). Reaching maxY switches to `hanging` on the anchor's ledge; reaching minY over a surface switches to `ground`. 16 full up-moves reach the top.
    - `hanging`: `dx * SHIMMY_STEP` along the segment, clamped (dz ignored). No transfer between ledges. `climb` mantles: the centre moves `MANTLE_DISTANCE` along `facing` and must land on an **authored floor or ramp top** within `STEP_HEIGHT` of the ledge (never a solid top) with the box fitting; otherwise nothing changes. The west mantle lands at (-9.5, 3, 4.5), the east one at (9, 3, -1.5).
    - `drop` from `climbing` or `hanging` switches to `falling`; in any other mode it's a no-op. `jump` while attached does nothing. No gravity applies while attached.
  - **Simulation:** the room's `simulate(dtMs)` runs fixed 50 ms steps (`SIM_RATE_HZ` 20) and carries the remainder over. Only `falling` players are stepped, so grounded players are never nudged. `autoSimulate` (default true) drives it from the room's simulation interval in real time; Mocha sets it to false and calls `simulate` itself, next to the `now` override.
- **Action rate limit:** one bucket per client, shared by **all** actions: `ACTION_RATE_HZ` 5 with `ACTION_BURST` 2, separate from the move bucket. Every accepted action spends a token, refused and no-op ones included (so a `drop` flood starves jumps). Moves while attached spend move tokens as usual.
- Token-bucket rate limit per client, server-side only: `MOVE_RATE_HZ` 20, `MOVE_BURST` 3. Every accepted message, turn-only included, spends one token. Over-budget moves are dropped silently, so sustained speed is at most 2.4 (ghost) and 2.0 (warden) units/s.
- `MyRoom.ts` exports `MOVE_RATE_HZ`, `MOVE_BURST`, `BOUND`, `PLAYER_HALF_SIZE` (re-exported from `shared/map.js`), `TEAM_STEP` (frozen, `TEAM_SPEED[team] / MOVE_RATE_HZ`), `MAX_CLIENTS`, `SPAWN_YAW` and `parseMove`. Since M4 it also exports `SIM_RATE_HZ` (20), `ACTION_RATE_HZ` (5), `ACTION_BURST` (2), `parseAction`, `CLIMB_STEP` (`CLIMB_SPEED / MOVE_RATE_HZ` = 0.075), `SHIMMY_STEP` (`SHIMMY_SPEED / MOVE_RATE_HZ` = 0.05) and `MANTLE_DISTANCE` (`2 * PLAYER_HALF_SIZE` = 1). `SPEED` is kept as a legacy export (`=== TEAM_STEP.warden`, 0.1); movement no longer uses it. `Tests/` imports these from `server/build/rooms/MyRoom.js`, so renaming or removing one breaks the tests.
- **M5 server (#41, #43, #46):**
  - `rules/ballistics.ts` (`aimDirection`, `castRay`, `segmentBlocked`): rays hit solids, floors, ramp wedges, the ground and player boxes; anchors and terminals are ignored. `rules/fire.ts` (`parseFire`). Fire and reload share one bucket (10/s, burst 3, spent only by valid messages; a refused reload spends a token). Then the weapon cooldown on `room.now()`, ammo > 0 and not reloading; a refused shot changes nothing. Reload completes in `step()` on `room.now()`, so Mocha drives it with `simulate()`.
  - Elimination (health 0): reload cancelled, move/action/fire/reload ignored with no token, a climber or hanger falls and settles. Bodies killed in the current step stay hittable until the next step (the later shooter gets damage 0, killed false). A dead player's seat stays; leaving and rejoining gives a fresh player.
  - **Visibility filter (#46):** Colyseus 0.18 `StateView`. `players` is tagged `.view()`, each client gets `client.view = new StateView()`, and `MyRoom.updateViews()` (every 50 ms step, on join, on leave) adds or removes players per client using `rules/visibility.ts` `canSee`. Ghost viewers see everyone; a Warden sees itself, its teammates, and any Ghost within `VISIBILITY_NEAR` or with a clear eye-to-sample ray (7 points: centre, head, feet, 4 shoulders). A hidden Ghost is absent from that client's `players` map. Worst case at 4v4 is about 0.6 ms per step. **Accepted leaks (decided on #38):** a hidden Ghost's patch can reach a Warden for up to one 50 ms step after it leaves sight; room size and join/leave are observable.
  - Colyseus closes any client that sends an unregistered message type (code 4002), so a forged unknown message disconnects only the forger. Test clocks in Mocha must start on a whole millisecond (float sums like 299.99999999999977 refused a shot, #52). Mocha: 163 tests; CI also runs `npx tsc --noEmit` in `server/` (#37 fixed).
- The server serves `client/dist` with `express.static`, so the whole game runs on one port (2567). `/playground` and `/monitor` are dev-only; with `NODE_ENV=production` both are off.

### Client (`client/`)
- `client/src/map.ts` `buildMap` renders `GRAYBOX_MAP`: the ground sized from `bounds`, one box per solid (`solid-<id>`; walls light grey, cover darker), and a green emissive post per terminal (`terminal-<id>`, no collision). Nothing in `client/` hard-codes the layout, and a unit test checks that.
- `client/src/map.ts` `buildTraversal(scene, map?)` (#33) renders the M4 lists separately, so `buildMap` still returns exactly `{ id, renderedSolids }`. It returns `{ renderedFloors, renderedRamps, renderedAnchors }` (4, 1, 6) and builds `floor-<id>` (blue-grey boxes, `floorMat`), `ramp-<id>` (a solid tan wedge, the same shape the server collides with, `rampMat`) and `anchor-<id>` (emissive cyan, one shared `anchorMat`: climb strips 0.3 wide from minY to maxY + PLAYER_HEIGHT, flush on the wall face; ledge bars 0.12 tall, topped at `ledge.y` on the edge face). All are non-pickable with frozen world matrices. `scene.ts` calls both; `GameScene` gains `traversal`.
- `client/src/players.ts` (`createPlayerRenderer(scene)`): graybox shapes built in code. Ghost is a slim dark-violet cylinder (0.7 x 1.8), Warden a bulkier orange box (1 x 1.8 x 1). Each has a yellow emissive nose on local +z near the top, and `body.rotation.y = yaw`. Your own player is tinted blue whatever its team. Until the team is known the player is a small neutral cube; the shape is rebuilt when the team arrives or changes. Mesh names: `player-<id>` and `player-<id>-nose` (a child). Body `metadata` is `{ team, isLocal }`. **Players are drawn at height** (#33): `position.y = y + bodyHeight / 2`, so the feet sit at the synced y in every mode (a hanger spans 1.2..3.0). `PlayerPose` (net.ts) has optional `y` and `mode`; a bad y gives 0 and an unknown mode gives `ground`.
- `client/src/cameras.ts` (`createCameraRig`): the mode follows your own team in server state. `overhead` (the old top-down ArcRotateCamera, beta 0.4, radius 56) until the team is known and after disconnect; `third-person` for a Ghost; `first-person` for a Warden.
  - Pointer lock on canvas click; Esc releases it. Only while locked, mouse X turns yaw and mouse Y tilts pitch at **0.0025 rad per pixel**. Pitch is local and never sent. Positive pitch looks down.
  - Ghost: orbits a shoulder point 1.7 up and 0.6 to the right, 3.2 back (camera height floored at 0.3), starting pitch 0.25, limits -0.5..1.0. No camera collision yet.
  - **Cameras at height** (#33): `setLocalPlayer(id, x, z, team, serverYaw, y = 0)` adds y, so the Warden eye is at `y + 1.6` (4.6 upstairs) and the Ghost shoulder at `y + 1.7`. Overhead is unchanged and frames the upper level too. The Ghost camera follows the server yaw, so it swings when a grab snaps the yaw to the anchor's facing (backlog).
  - Warden: eye 1.6 above the feet on the player's server x/z, pitch limits -1.4..1.4, near plane 0.05, fov 1.0. **Your own body and nose are hidden in first person** (`isVisible = false`, checked every frame because the mesh can be rebuilt).
  - `#camera-hint` (bottom centre, separate from `#hud`) says "Click to look around (Esc releases the mouse)" in team modes while the pointer isn't locked.
- **M5 client (#48, #50):** `client/src/vitals.ts` (pure: `isEliminated`, `defaultVitals`, `healthText`, `ammoText`, `crosshairVisible`). DOM `#health` (`HP 100/150` or `Eliminated`), `#ammo` (`Ammo 30/30`, `Reloading...`, `R: reload`), `#crosshair` (hidden in overhead and when eliminated). An eliminated body is rebuilt as a flat 0.3 high grey box (`eliminatedMat`, metadata `eliminated: true`). Remote players removed by the filter are disposed at once and rebuilt on re-add. `#hud` counts only the players this client was sent (a Warden sees 1 or 2 in 1v1). Fire/reload: `FireInput` and `FIRE_BINDINGS` in `input.ts` (left mouse held fires only if the button went down while pointer-locked, so the locking click never fires; R sends one reload per press; inactive in overhead, disconnected, eliminated). The 20 Hz tick sends `fire { yaw, pitch }` (pitch = `-rig.pitch`) through `firePacer.ts`, which paces to the weapon interval and skips sending at ammo 0 or while reloading. `combat.ts`: tracer mesh `tracer` (70 ms), `#hit-marker` (class `kill` on a kill, 140 ms), `#damage-flash` (220 ms). The hook gains `health`, `ammo`, `reloading` per player and additive `events = { shots, hits, kills, damaged }` counters (version still 1).
- It joins `my_room` (`client/src/net.ts`). The WebSocket URL comes from `location` (`wss:` on https; on the Vite dev port 5173 it uses port 2567 on the same host).
- Input (`input.ts`, `main.ts`): one shared **20 Hz tick** combines keys and camera yaw. With WASD or arrow keys held it sends `{ dx, dz, yaw }` (keys as -1/0/1, yaw = camera yaw). With no keys held it sends a yaw-only `{ dx: 0, dz: 0, yaw }` only when the camera yaw differs from the last sent yaw by more than 0.01 rad. Nothing is sent when idle, on load or on focus. In overhead mode keys send `{ dx, dz }` with no yaw. Nothing moves locally; meshes follow server state (no smoothing yet). W/S and A/D send dz/dx in every mode; the server reads them as climb and shimmy when attached.
- **Actions** (#35, `ActionInput(onAction, target = window)` in `input.ts`, table `ACTION_KEYS`): `Space` sends `{ action: 'jump' }`, `KeyE` `{ action: 'climb' }` (attach, grab, mantle) and `KeyC` `{ action: 'drop' }`, through `sendAction(room, action)` in `net.ts`. Exactly one message per press: auto-repeat and a second keydown before keyup are ignored, a blur clears held keys, and Ctrl/Meta/Alt combinations are ignored and not prevented. Every action keydown calls `preventDefault()`, so Space never scrolls.
- **Mode HUD** (#35, `client/src/traversalHint.ts`): `#mode`, just below `#hud`, shows exactly one of (`MODE_TEXT`) `On the ground`, `In the air`, `Climbing: W/S climb up or down, C drop` and `Hanging: E climb up, C drop, A/D move`; it is empty before the local state arrives and after disconnect. `#hud` itself is unchanged. `#climb-prompt` (centre, cyan) shows `E: climb` or is empty. It shows only for a team with `CAN_CLIMB` (never a Warden), in ground or falling mode, when `nearAnchor(x, y, z)` holds with the server's range and reach. It reads only shared map data and the local server position and doesn't check box fit; the server decides.
- The HUD (`#hud`) shows "connecting...", "online, N players, you are a Ghost" (or "a Warden"), "offline" or "disconnected". If WebGL fails to start, the page shows a message instead of a blank canvas.
- **Test hook** (`client/src/testHook.ts`, types in `shared/testhook.d.ts`): `window.__blacksite.snapshot()` returns a fresh plain copy on every call:
  `{ version: 1, connected, sessionId, localTeam, players: [{ id, x, y, z, isLocal, team, yaw, mode }] (sorted by id), map: { id, renderedSolids, renderedFloors, renderedRamps, renderedAnchors }, camera?: { mode, yaw } }`. `y` and `mode` (#33) are as received; they are 0 and `ground` before a value arrives.
  `team` is `Team | null` and `yaw` a number, both from received state only; `localTeam` is the local player's team. `camera` is present once the game scene exists (always, in a browser that loaded) and absent if WebGL failed. After rendering, `map` is `{ id: 'graybox-1', renderedSolids: 16, renderedFloors: 4, renderedRamps: 1, renderedAnchors: 6 }` (also in a tab that never joins); before, `id` is null and every count is 0. The hook is installed before WebGL starts, is frozen and can't be replaced. It ships in the production build and shows only what the client received. `connected` turns true before the players arrive, so poll for the player count. Fields may be added in version 1; bump `version` only when a field is removed or changes meaning.

## Gotchas
- **Run only one agent at a time.** Agents share one working tree and one git index, so a parallel run can commit another agent's work. This happened once: an agent's commit included another agent's staged deletions. Always stage only your own folders (`git add <your folders>`), never `git add -A`.
- **Commit messages say `refs #N`, never `closes #N`.** `closes` makes GitHub close the issue on push, before CI has run. The agent closes its issue itself, with a comment linking the green run.
- **Don't comment on other agents' issues.** The owner's permission settings block it. Put notes for the next agent in your commit message and in the closing comment of your own issue.
- **The 20 Hz send timer shares the main thread with rendering**, and the server doesn't make up for missed ticks. On a slow machine (or headless tabs with software rendering) players move slower than their team speed; two headless tabs at 800x600 ran at about 11-14 Hz. The camera specs use a 320x240 viewport for this reason. Speed tests must allow for the tab's real send rate.
- Headless Chromium on Linux misbehaves under a real pointer lock (see Tests). Windows doesn't, so a camera test can pass locally and fail in CI; use the `lockPointer()` / `moveMouse()` helpers.
- The terminal meshes are named `terminal-terminal-a` and `terminal-terminal-b`, because the mesh name is `terminal-<id>` and the ids already start with `terminal-`. It's cosmetic; tests rely on the `terminal-<id>` pattern, so don't "fix" one side alone.
- On Windows, `npm test` in `server/` passes, then crashes when Mocha exits (`UV_HANDLE_CLOSING` assertion). It works fine on Linux CI, so trust CI.
- Synced numbers travel as float32: compare positions and yaws in tests with a tolerance (about 1e-4), not exact equality. Compare yaws modulo 2 pi: the server wraps them, so pi can arrive as -pi.
- Each client starts with a move budget of 3, and turn-only moves spend it too. A test that sends more than 3 moves back to back without waiting about 50 ms between them will see the later ones ignored.
- On this PC, `gh` is at `C:\Program Files\GitHub CLI\gh.exe` (in Bash: `"/c/Program Files/GitHub CLI/gh.exe"`); run it from inside the repo. Its login (Vignex-tech) has the `repo` and `workflow` scopes. `gh issue view` takes either `--comments` or `--json`, not both.
- **Assert once, after the SDK clients leave.** Thousands of `expect()` calls while SDK clients are connected (one per sample of a 25 ms sampler) blocked a Playwright worker for about 8 s, and the server's WebSocket ping dropped the SDK clients with code 1006 (#34). Collect per-sample problems in arrays and assert once per client after the SDK clients have left.
- **If an agent is cut off by a usage limit,** check `git status` for its uncommitted work and hand it to a fresh agent instead of discarding it (this happened on #36).
- **The action budget is 5/s with a burst of 2, shared by jump, climb and drop**, and refused or no-op actions spend tokens too. Tests that press keys or send actions should space them out (about 500 ms between presses is safe).
- Walk residue can leave y at about 1e-10 instead of 0 on a ramp's low edge; compare y within 1e-4.
- **Read the truth about a Ghost from a Ghost client (#45).** Since the filter, a Warden client is not sent hidden Ghosts. Specs read any player's truth from a Ghost client (`godView`) or from the player's own client, and wait for a Warden to be sent a Ghost with `whenVisible` only after placing it in sight. Never assert on `unsure` placements. Mocha reads room state directly (unfiltered), but must not read a Ghost from a Warden client object.
- **Guard `room.leave()` with `connection.isOpen`** (use `leaveQuietly`). Leaving a closed connection hangs the test.
- **Colyseus closes a client that sends an unregistered message type (code 4002).** A forged unknown message type disconnects the forger; test forged payloads with registered types.
- **`page.mouse.down/up` never reached window listeners once the `lockPointer` stand-in was in place (#51).** Dispatch left-button mousedown/mouseup on the canvas inside the page, like `moveMouse`. The client handlers are the real ones.
- **Test clocks start on a whole millisecond** (#52). Fake-clock float sums like 299.99999999999977 refuse a shot that the cooldown says is due.
- **E2E is now about 3.5 min in CI** (3.7-3.8 locally). New specs for M6 must add very little time.
- A Warden on the stairs at z 4.5 is blocked by the catwalk slab edge for shots; z 3 works. Hidden-Ghost coordinates in wire-scan tests must not be round numbers.
- Git: user.name is set only in this repo (`Vignex-tech`). There are LF/CRLF warnings on commit; they're harmless.
